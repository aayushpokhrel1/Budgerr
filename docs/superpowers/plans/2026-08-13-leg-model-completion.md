# Complete the bet-leg model (`game_id`/`player_id`/`market`) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add structured, join-able identity (`game_id`, `player_id`, `market`) to every stored bet leg so builder legs carry the exact CLV join keys Playstat specified, and clean up team-leg display to render from the new `market` field instead of a folded string.

**Architecture:** Three nullable columns are added to `bet_legs` (backend, no backfill). The byte-identical `builderConstructionToBetInput` in both frontends populates them at log time and stops folding the market into `player_name`/`stat_type` for team legs. Post-log leg rendering shows a human market label when `market` is set, else falls back to `stat_type` (so legacy rows and player legs are unchanged). No CLV read/UI — this is plumbing only.

**Tech Stack:** FastAPI + SQLAlchemy + Alembic (backend, Python 3.11, `backend/.venv`), Next.js + Vitest (budgerr-web), Expo/React Native + tsc (BudgerrApp).

## Global Constraints

- Spec: `docs/superpowers/specs/2026-08-13-leg-model-completion-design.md`.
- All three new columns/fields are **nullable/optional**. No backfill of existing rows.
- `lib/builderParlays.ts` MUST stay **byte-identical** across `budgerr-web` and `BudgerrApp` (verified by `diff`). Any change lands identically in both.
- **No** `clv`/`value`/`edge`/`closing` naming anywhere. No CLV read job, endpoint, or UI in this work.
- Team legs stay **log-only** (excluded from auto-settle). Do not add team-market settlement.
- CLV join keys (for reference — what the fields must satisfy): player = `(game_id, player_id, stat_type, line_value)` + side; team = `(game_id, market, line_value)` + side. `market ∈ {first_inning_runs, f5_runs}`.
